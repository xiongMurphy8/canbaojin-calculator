# 第二轮评审：数据覆盖广度测试（画像4—6）

评审日期：2026-08-18  
评审分支：`review-round-2-data-coverage`  
评审方式：只读配置审查 + 官方来源核验 + 按当前 JavaScript 逻辑复算。未修改参数、公式、合规文案或生产代码，未部署。

## 🚨发现潜在合规风险

### 1. 东莞2025年度参数会被错误标记为适用于2024年度

`CITY_POLICY['东莞']` 只有一个上限值36,993元，字段为 `verifiedThrough: 2025`。`applyCityPolicy()` 使用 `year <= verifiedThrough` 判断“当前有效”，因此目标年度选择2024时也会自动带入2025通告金额，并显示“2024年度官方口径已匹配”。配置缺少 `validFrom/effectiveYear`，把“核验截至”错误当成了“所有更早年份均适用”。

建议将地区参数改为按年度索引，并要求 `targetYear` 精确命中对应年度。此处只涉及参数选择逻辑，不建议自动回填历史年度。

### 2. 最低工资没有年度版本，2024年度也会使用2025年标准

21市 `minWage` 只有单个当前值，且 `applyCityPolicy()` 不按 `targetYear` 选择版本。用户选择2024年时，系统仍自动使用自2025-03-01起执行的标准估算工资成本。该错误会改变“扣工资社保后净收益”，尤其影响低薪劳动密集型企业。

建议配置 `effectiveFrom/effectiveTo/source/checkedOn`，历史年度没有官方值时停止自动带入。最低工资版本调整不属于残保金公式修改，但属于金额参数变更，仍应人工复核。

### 3. IP/设备位置可能替代企业申报管辖地，跨市企业容易匹配错误

页面唯一字段是“企业所在地”，自动定位取访问者当前IP或设备位置；代码没有注册地、主管税务机关、参保地、工资发放主体或残联联网认证所属行政区字段。注册地佛山、HR在广州办公时，IP可能自动选择广州，并使用广州参数。当前无“双地匹配”或冲突提示逻辑。

建议定位结果只能作为填写辅助，不能直接视为政策管辖地；应要求用户确认“残保金主管税务机关/联网认证所属行政区”。该口径涉及属地认定，**⚠️需人工审核**。

### 4. 广州精确金额使用的是明显过期的历史上限

广州其他区、增城、从化确有独立参数，但代码来源是2017年征收标准，`verifiedThrough: 2021`。目标年度2026时页面会标记历史参考值，但 `hasCorePolicy` 只判断金额大于0，仍会生成精确到分的老板结论。醒目标记不足时，用户可能把历史试算当成2026现行申报金额。

建议历史上限只能进入“敏感性试算”，主结论显示“待核验”，不得与现行参数使用同一种确定性视觉。**⚠️需人工审核**，且不得弱化现有“历史参考/待核验”提示。

## 4. 画像4：广州增城区企业主

### 输入

- 地区：广州增城区
- 上年平均人数：100人
- 工资总额：6,000,000元（年平均工资60,000元）
- 现有残疾职工年平均人数：0人
- 目标年度：2026
- 入职月份：1月；普通认定系数1
- 工资2,500元/月、企业社保公积金1,900元/月

### 当前代码输出

| 项目 | 输出 |
|---|---:|
| 自动上限 | 30,804.80元（2021历史参考） |
| 基准差额人数 | 1.50人 |
| 基准档位 | 90% |
| 现在预计应缴 | 41,586.48元 |
| 满额方案 | 新增2人 |
| 合作后应缴 | 0.00元 |
| 残保金节省 | 41,586.48元 |

| 最终净收益 | -64,013.52元 |

### 评价

- 特殊分区选择逻辑存在且能正确选到增城历史值。
- 但该金额不代表2026现行口径；当前系统仍给出精确金额，只依靠状态文案提示“历史参考”。
- 结论应优先显示“2026上限待核验”，历史值只能作为单独的敏感性场景。

## 5. 画像5：注册地佛山、实际用工在广州的跨市企业

### 当前系统行为

- 只有一个 `city` 字段，标题是“企业所在地”。
- 自动定位使用访问网页的设备/IP所在地，而不是企业注册信息、主管税务机关或参保信息。
- 若选择佛山：最低工资自动变为2,080元，但计征工资上限为空，系统停止输出金额。
- 若HR在广州访问且接受IP结果：会进入广州分区路径并可能用广州历史上限试算。

### 已知局限

当前无“注册地 + 参保地/用工地”双地匹配功能，也无冲突处理。不能声称系统会自动判断应适用佛山还是广州。正式口径应由企业主管税务机关及残联联网认证所属行政区确认。

### 产品建议

增加以下三个独立字段，但在官方口径明确前不自动决定：

1. 统一社会信用代码注册地；
2. 残保金主管税务机关/申报行政区；
3. 残疾职工社保参保及联网认证行政区。

若三者不同，只显示“存在跨地情形，需人工核验”，不自行编造双地算法。**⚠️需人工审核**。

## 6. 画像6：低薪劳动密集型企业

### 输入

- 广州其他区；上年平均人数200人
- 工资总额6,000,000元，企业年平均工资30,000元
- 现有残疾职工年平均人数0人
- 历史参考上限36,292元
- 月工资2,500元、企业社保公积金1,900元

### 当前代码输出

| 项目 | 输出 |
|---|---:|
| 计征基数 | min(30,000, 36,292) = 30,000元 |
| 差额人数 | 3.00人 |
| 当前应缴 | 81,000.00元 |
| 满额方案 | 新增4人 |
| 残保金节省 | 81,000.00元 |
| 用工成本 | 211,200.00元 |
| 最终净收益 | -130,200.00元 |

### 评价

- 代码正确执行“企业年平均工资与计征上限取低值”，不会把高上限强行当作企业工资。
- 需澄清：计征上限通常对应当地社会平均工资2倍口径，并不是“当地最低工资2倍”。页面当前用“计征工资上限”表达，方向正确。
- 月最低工资用于新增员工工资成本/合规底线，企业年平均工资用于残保金计征，两者语义不同；建议在界面上物理分区，避免老板混淆。
- 2026测算使用2025最低工资尚可作为当前参考，但必须显示文件生效日；选择2024时不得沿用。
